# x402 public agent runs (Week 3)

Unauthenticated callers pay once (MockUSDC on BSC Testnet **97**), then call the public run API.  
**Cooker UI keeps using SIWE `POST /agent/runs` for free.**

## Endpoint (to implement)

`POST /agent/public/runs`

Body (same spirit as SIWE runs):

```json
{
  "goal": "Saya mau masak ayam semur",
  "pantry": ["chicken", "onion"],
  "selectedDish": "Ayam Semur"
}
```

## Payment flow

1. Client calls without payment proof → **HTTP 402** + payment requirements JSON (`payTo`, `amount` atomic mUSDC, `chainId` 97, `token` = `MOCK_USDC_ADDRESS`).  
2. Client transfers MockUSDC to `X402_PAYTO` for at least `X402_PRICE`.  
3. Client retries with proof header, e.g. `X-PAYMENT-TX: 0x…` (exact header name TBD in implementation; document here when shipped).  
4. Server verifies on-chain Transfer to `X402_PAYTO` ≥ price → runs orchestrator → returns `{ ok, runId, status, steps, … }`.

Prefer official `@x402/express` + facilitator when BSC-testnet MockUSDC is supported; otherwise minimal RPC verify against env (see plan Track E).

## Env

```env
X402_ENABLED=true
X402_PAYTO=0xYourTreasury
X402_PRICE=10000
MOCK_USDC_ADDRESS=0x...
BSC_RPC_URL=https://data-seed-prebsc-1-s1.bnbchain.org:8545
CHAIN_ID=97
```

`X402_PRICE` is **atomic** (6 decimals). `10000` = 0.01 mUSDC.

## Curl sketch (after implementation)

```bash
# Expect 402
curl -sS -X POST "$API/agent/public/runs" \
  -H 'content-type: application/json' \
  -d '{"goal":"mau masak ayam semur"}'

# After paying on-chain:
curl -sS -X POST "$API/agent/public/runs" \
  -H 'content-type: application/json' \
  -H 'X-PAYMENT-TX: 0xYourTxHash' \
  -d '{"goal":"mau masak ayam semur"}'
```
